# Installable web app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Instalar o Monitora Timbó pela tela inicial e apresentar uma experiência própria sem conexão, sem valores antigos.

**Architecture:** Manifesto nativo do Next.js e service worker pequeno, sem dependências novas. Uma página estática fornece o fallback offline; o painel aberto usa estado explícito de disponibilidade e invalidação de requisições para impedir que respostas antigas restaurem medições.

**Tech Stack:** Next.js 16.3.4, React 19, TypeScript, Service Worker, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-31-web-app-design.md`

## Global Constraints

- Primeiro o botão **Instalar aplicativo**; logo abaixo, **Adicione à tela inicial e abra como aplicativo.**
- Sem título adicional e sem a frase “Sem loja de aplicativos.”
- Não apresentar medições, gráficos, histórico ou previsão antigos no estado sem conexão, inclusive quando a conexão cair com o painel já aberto.
- Restaurar as informações apenas depois de uma consulta online bem-sucedida.
- Não armazenar HTML dinâmico do painel, respostas das APIs de dados, medições ou previsão no cache offline.
- Não alterar o coletor, a frequência de coleta, SQLite ou o acesso somente leitura às APIs.
- Sem novas dependências de produção; preservar estilos e conteúdo existentes fora dos estados aprovados.

## Review Focus

- Resposta iniciada antes de ficar offline: não deve reexibir valores depois da queda (Task 2).
- Sinal online com servidor indisponível: manter campos vazios e mensagem de indisponibilidade, sem declarar ausência de internet (Task 2).
- Navegação RSC do Next.js: não responder HTML offline a requisições de dados/framework (Task 1).
- Instalação recusada ou indisponível: conservar acesso às instruções e evitar prompt automático (Task 3).
- Atualização do service worker: cache antigo removido sem apagar caches de outras aplicações (Task 1).

### Task 2: Conectividade e proteção contra dados antigos

**Files:** Create `site/lib/connectivity.ts`, `site/components/monitor/connection-state.tsx`, `site/tests/connectivity.test.ts`, `site/tests/connection-state.test.ts`. Modify `site/components/monitor/use-refresh.ts`, `site/components/monitor/dashboard.tsx`, `site/app/globals.css`.

**Interfaces:** `ConnectionStatus = 'ready' | 'offline' | 'checking' | 'unavailable'`; controlador em `lib/connectivity.ts` com `getStatus()`, `subscribe(listener)`, `markOffline()`, `beginCheck(): number`, `completeCheck(token:number, success:boolean)`, `dispose()`. `useRefresh` expõe `connectionStatus` e `retryConnection(): Promise<void>`; `ConnectionState({status,onRetry,busy})` apresenta estado sem medições.

- [ ] Criar testes de transições do controlador: ready→offline; online→checking; falha→unavailable; sucesso válido→ready. Invalidar token ao cair a conexão e ignorar conclusões anteriores. Testar que só um novo par de dashboard/histórico bem-sucedido pode liberar o estado ready após queda.
- [ ] Criar teste de renderização estática do estado de conexão: contém aviso, “—” e botão; não contém valores das fixtures nem gráfico. Testar mensagem distinta para servidor indisponível.
- [ ] Rodar `cd site && npx vitest run tests/connectivity.test.ts tests/connection-state.test.ts`, confirmar falha inicial.
- [ ] Implementar controlador e integrar eventos online/offline e retorno à aba; checar `navigator.onLine` na montagem sem usá-lo durante SSR. Ao ficar offline invalidar requisições pendentes de dashboard/histórico. Usar `cache:'no-store'` nos fetches. Falhas de consulta escondem valores, substituindo o comportamento atual de manter dados anteriores visíveis.
- [ ] Para recuperar de falha, consultar dashboard e histórico do período selecionado e publicar resultados somente após ambos terem sucesso no token atual. Não reexibir histórico antigo durante a recuperação. Resposta válida do servidor com dados de coleta atrasados segue as regras existentes de apresentação online.
- [ ] Integrar `ConnectionState` no painel antes da área que apresenta clima, rio, chuva e previsão; enquanto bloqueado, não renderizar essa área nem informações de tema derivadas de previsões antigas. Manter cabeçalho, rodapé e conteúdo institucional. Botão de nova tentativa informa progresso acessível e evita duplicar consultas.
- [ ] Rodar testes novos, testes existentes de apresentação e `npm run typecheck`. Registrar falhas preexistentes separadamente, sem mudar layout alheio ao escopo. Commit desta tarefa.

- [ ] Escrever testes: standalone via display-mode e sinal iOS oculta convite; dispensa persiste na sessão; armazenamento bloqueado não quebra; iPhone recebe instruções Safari; ausência/recusa do prompt mantém caminho manual; `appinstalled` oculta convite.
- [ ] Rodar `cd site && npx vitest run tests/pwa-install.test.ts`, confirmar falha inicial.
- [ ] Implementar convite abaixo do cabeçalho e antes do painel, visível só em layout mobile até 800px. Copiar textos aprovados sem título extra. Adicionar controle de dispensa com nome acessível. Não disparar prompt ao carregar.

Android: menu do navegador → instalar/adicionar à tela inicial. Navegadores internos devem orientar abertura no navegador do aparelho, sem prometer instalação automática.
